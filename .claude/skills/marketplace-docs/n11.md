`N11Products.cs`, `N11PriceInventory.cs`, `N11References.cs`; SOAP: `N11Returns.cs`, `N11Invoices.cs`,

## Connection
- `https://api.n11.com/`: `/ms` products, `/cdn` categories, `/rest` orders, `/ws` SOAP. No sandbox — every
  connection is live.
- REST headers `appkey`, `appsecret`; SOAP `<auth><appKey/><appSecret/></auth>`. Integrator name "Ravencia" on writes.

## Limits (per minute; bucket chosen by path)
orders (`rest/`) 600 — n11 documents 1000; products (`ms/`) 120; tasks (`ms/product/task`) 120; categories (`cdn/`)
30; SOAP (`ws/`) 60; question list 1, enforced as 75 s spacing (n11 sometimes refuses exactly 60 s). Non-order values
are cautious guesses. A real 429 carries Retry-After.

## Windows and paging
- `GET rest/delivery/v1/shipmentPackages?startDate&endDate` (epoch ms), `orderByField=true` (last-modified),
  `orderByDirection`, `sender=ALL`, page/size ≤ 100. Max 15 days per query, longer is silently trimmed — code uses 14.
  No data before 2024-11-01. First read 3 months; overlap ≥ 600 s.
  A page without `totalPages` is not taken for the last one: a non-empty page is followed by the next until an empty
  page ends the walk (`N11OrderMapper.Packages`, report item 15, 5 Nov 2026).
- A 403 HTML page is a gateway block (N11_GATEWAY_BLOCKED, RateLimit, 15 min), on REST and SOAP alike; a 401, or a 403
  that is not a page, stays N11_CREDENTIALS_REJECTED (`MarketplaceErrorRules`, report item 16). Before, an HTML 403 on
  SOAP read as credentials.
- Products `ms/product-query`: page ≤ 250, no modified filter → every read is a full scan.
- Claims (SOAP): page 20 fixed, request-date filter only.
- Tasks: first poll after 5 s; 30-min timeout if not PROCESSED.

## Time
REST epoch ms documented as GMT+3, treated as UTC. SOAP dates without offset are Turkey time.

## Sale state (T2-D30, 2026-11-05)
- `ms/product-query` items carry `saleStatus`: On_Sale, Out_Of_Stock, Sale_Closed, Before_Sale (SOAP GetProductList:
  1 Satış Öncesi, 2 Satışta, 3 Stok Yok, 4 Satışa Kapalı); `status` Suspended closes a product too. Sources: n11 doc
  sample (`N11ProductMapperTests`, "saleStatus":"On_Sale"), magazadestek.n11.com "RestAPI Satıcı Ürün Sorgulama"
  (On_Sale, Out_Of_Stock; 403 to WebFetch, seen via WebSearch) and a third-party guide (all four): the full enum is
  **unverified**. Unknown values stay unknown. Code: `N11ProductMapper.Sale`.

## Statuses
- Package: Created → New, Picking → Processing, Shipped, Delivered, Cancelled, UnSupplied → Cancelled, UnPacked =
  parent of a split (superseded), unknown → manual review.
- Claims: REQUESTED → Created; APPROVAL_WAITING/PENDING/PENDED → WaitingInAction; APPROVED → Accepted; DENIED →
  Rejected; CANCELLED; MANUAL_REFUND → Refunded.
- Tasks: IN_QUEUE, PROCESSED, REJECT; per SKU SUCCESS/FAIL.

## Quirks
- `sender=ALL` is needed to see n11depom (n11 warehouse) packages and SKUs; an n11depom SKU takes price updates only.
- Location-specific deliveries have no package id. A split leaves the parent UnPacked and n11 does not name the
  origin — the code infers it.
- Since 3 Aug 2026 `deliveryAddressType` is KTN, EASYPOINT or PUP; the customer is then read from `billingAddress`.
- No invoice state, only `invoiceLink`; an empty link proves nothing (panel uploads leave it empty).
- Price/stock: `listPrice` ≥ `salePrice`, 2 decimals, stock ≤ 999,999. No webhooks.
- Settlement lines (`ws/settlementService/` GetSettlementDetail): fees n11 leaves out are 0. A line without
  `orderItemId` or `settlementAmount` (the payout's figure), or with a money field that cannot be read (O5:
  "1234,50"), is not stored and opens a FINANCE_RECORD_INCOMPLETE issue; the day's other lines are stored (5 Nov
  2026; before, it failed the page). Source: `N11Settlements.cs`, SettlementService.wsdl.
- Package totals: `totalAmount` ("Toplam tutar") and `totalDiscountAmount` ("Toplam indirim tutarı") at package level;
  the docs do not say what they include (the sample's 1479.79 matches no line sum). Lines: `price` is the unit price
  before discounts, `sellerInvoiceAmount` = price × qty − `totalSellerDiscountPrice`. The panel keeps the line sums and
  takes the package totals only when a line is unreadable (5 Nov 2026). No currency field (lira). No order-date field:
  the order date is the package's `packageHistories` creation entry; a package without one is refused and its order
  read again, `lastModifiedDate` is never the order date (5 Nov 2026). Source:
  developer.n11.com/documentation/n11-siparis-entegrasyonu/siparis-listeleme-servisi/, `N11OrderMapper.cs`.
- Return deny (ClaimReturnDeny, SOAP `ws/returnService/`): `claimReturnId`, `denyReasonId` (ClaimReturnDenyReasonTypes
  ids, e.g. 21, 1, 2, 22, 23, 3, 24, 25, 41), `denyReasonNote`, `returnShipmentType` CUSTOM or CAMPAIGN,
  `shipmentCompanyId` (ShipmentCompanyService GetShipmentCompanies), `trackingNumber`, `deliveryReceiptNumber`,
  image/video URLs. Reason 41 ("İade Ürün Mağazaya Ulaşmadı") takes no shipment type (n11 uses the buyer's tracking
  number). CAMPAIGN approves the return once the seller ships with the campaign code (`sellerCampaignNumber` in
  ClaimReturnList), so the panel never sends it: other reasons go as CUSTOM with carrier and tracking number
  (`N11ReturnDenyRule`). The page contradicts itself on whether CUSTOM takes `trackingNumber`/`shipmentCompanyId`;
  the panel sends both. Answer: `result/status` success|failure only. Not tried on live yet (5 Nov 2026). The
  GetShipmentCompanies answer is not documented on the portal; companies are read from elements with id + name.
  Source: https://developer.n11.com/documentation/iade-entgrasyonu/iade-talepleri-servisi/ (read 5 Nov 2026).
- Each claim covers one product, so an order whose claims were approved and rejected is shown "Kısmen Onaylandı" at
  order level (`OrderReturnPartialApprovalPolicy`).
